# 3.1 — The metaspace trick

## One-line answer

SentencePiece replaces every space with `▁` (U+2581) instead of splitting on it, so whitespace becomes
**data** rather than a delimiter — which restores the exact round trip WordPiece lost on `'a  b'` and on
newlines, and still loses a tab and a leading space, both silently.

---

## The story

Someone reads out a phone number and you write it down in groups: 020, 7946, 0018. Easy to read back.

Then they give you a reference code with a space in the middle that *matters* — the space is part of the
code. You have been writing spaces as gaps between groups, so now you cannot tell which gaps are yours and
which are theirs. Your own formatting has become indistinguishable from the data.

The fix is not to write more carefully. It is to stop using a gap to mean two different things: write a
visible mark for the code's own space, and keep gaps for your grouping.

---

## The idea in plain language

Every tokenizer before this one has had a **pre-tokenizer**: a rule that cuts text into chunks that merges
may never cross. Day 12 part
[1.4](../../../day-012-bpe-the-merge-loop/parts/01-the-merge-loop/1.4-the-pre-tokenizer.md) introduced it,
Day 13 gave it the published regex, WordPiece part
[1.2](../01-wordpiece/1.2-the-hash-hash-convention.md) used a whitespace splitter.

The pre-tokenizer exists to stop nonsense merges across word boundaries. It also, in the WordPiece
configuration, **eats the whitespace** — and part
[1.4](../01-wordpiece/1.4-the-word-that-became-one-unk.md) measured what that costs: every newline in the
corpus gone, 1,646 of them, plus 158 `#` characters destroyed by the marker collision.

SentencePiece takes a different route. Instead of splitting on spaces, it **replaces** them:

```text
"The plan costs zero."   ->   "▁The▁plan▁costs▁zero."
```

`▁` is U+2581 LOWER ONE EIGHTH BLOCK — a printable character that essentially never occurs in real text.
Now there is no whitespace left to discard, because there is no whitespace: it has become an ordinary
character in an ordinary string, and the tokenizer treats the whole input as one sequence.

This is the same move Day 13 part
[3.2](../../../day-013-bpe-encode-decode-bytes/parts/03-byte-level-bpe/3.2-the-byte-to-unicode-trick.md)
made with `Ġ`, arrived at independently. Both say: **whitespace is data, so encode it rather than
delimiting with it.** And both avoid part 1.2's `##` collision for the same reason — the marker is a
character no real text contains.

The name in the `tokenizers` library is `Metaspace`, and it is a pre-tokenizer in the API only. What it
actually does is a substitution.

---

## Why Akshara needs it

**Because Akshara must reproduce whitespace exactly.** Code, markdown, poetry, anything indented. A
tokenizer that returns one space where four were is not a small inaccuracy for a model that writes Python.
This part is the mechanism that makes it possible, and Day 16 chooses it or something like it.

**Because it is the third independent solution to one problem**, and seeing three makes the problem visible
rather than the solutions. `Ġ`, `##`, `▁` — two of them work, one does not, and the difference is a
property you can now state in one sentence.

**Because the popular one-line description of it is wrong**, and step 4 measures why. "SentencePiece has no
pre-tokenizer" is repeated everywhere; the object prints `split=True` and behaves accordingly. Checking a
slogan against the thing it describes is the habit this whole day is training.

---

## The mechanism

### Step 1 — the substitution

```python
from tokenizers import pre_tokenizers

ms = pre_tokenizers.Metaspace()
print(ms)
print(ms.pre_tokenize_str("The plan costs zero."))
```

**Line by line:**

- `Metaspace()` with defaults. Printing the object shows every parameter, which is the habit Day 14 part
  [2.1](../../../day-014-tiktoken-and-the-pipeline/parts/02-the-tokenizers-pipeline/2.1-five-stages-not-one.md)
  established — the defaults are behaviour, and behaviour should be visible.
- `pre_tokenize_str` runs stage 2 alone.

Measured, `tokenizers==0.23.1`:

```text
Metaspace(replacement="▁", prepend_scheme=always, split=True)
[('▁The', (0, 3)), ('▁plan', (3, 8)), ('▁costs', (8, 14)), ('▁zero.', (14, 20))]
```

Three parameters, and each one matters:

- **`replacement="▁"`** — the substitute character. Changing it changes every id, and it is stored in the
  tokenizer file, which is Day 14 part
  [3.1](../../../day-014-tiktoken-and-the-pipeline/parts/03-the-remaining-gap/3.1-the-file-is-the-contract.md)'s
  argument working.
- **`prepend_scheme=always`** — a `▁` is added at the **start** of the string, so `The` becomes `▁The` and
  tokenizes identically to a `The` in mid-sentence. This is exactly `add_prefix_space` from Day 14 part
  [3.3](../../../day-014-tiktoken-and-the-pipeline/parts/03-the-remaining-gap/3.3-the-mismatch-the-library-will-not-catch.md)
  — the flag whose flip made 4 of 4 probes disagree. Here it is on by default.
- **`split=True`** — still cuts at the `▁` marks. So this *is* doing some splitting; what it does not do is
  throw anything away.

### Step 2 — the whitespace survives

This is the test WordPiece failed in part 1.4. Same probes, same corpus, this configuration:

```python
for s in ["The plan.", "a  b", "line1\nline2", "  indented", "\ttab"]:
    out = ug.encode(s)
    print(f"  {s!r:16s} -> {str(out.tokens):40s} decode={ug.decode(out.ids)!r:16s} "
          f"same={ug.decode(out.ids) == s}")
```

**Line by line:**

- Five probes, printed with tokens **and** decode **and** the equality, so nothing has to be inferred. The
  last two rows are the ones that fail, and they would be invisible if only the tokens were shown.
- `ug.decode(out.ids)` is called twice — once to print and once to compare. Wasteful and clearer than
  binding it; this is teaching code, and Day 12's rule about reading over cleverness applies.
- The probe list is deliberately the same one part
  [1.2](../01-wordpiece/1.2-the-hash-hash-convention.md) used against WordPiece, plus a tab. Identical
  probes across families is what makes part [4.1](../04-together/4.1-nine-tokenizers-one-table.md) a
  comparison.

Measured:

```text
  'The plan.'      -> ['▁The', '▁plan', '.']                   decode='The plan.'      same=True
  'a  b'           -> ['▁a', '▁', '▁', 'b']                    decode='a  b'           same=True
  'line1\nline2'   -> ['▁line', '1', '\n', 'l', 'ine', '2']    decode='line1\nline2'   same=True
  '  indented'     -> ['▁', '▁in', 'd', 'ent', 'ed']           decode=' indented'      same=False
  '\ttab'          -> ['▁', '\t', 't', 'a', 'b']               decode='tab'            same=False
```

**The first three round-trip exactly**, where WordPiece lost all three. Read row two: `'a  b'` gives
`['▁a', '▁', '▁', 'b']` — **two separate `▁` tokens** for the two spaces. The count is preserved because
each space became a character, and characters are counted. Row three keeps the newline as a literal `'\n'`
token.

**And the last two do not round-trip**, which is the more useful half of this measurement. Metaspace is not
"lossless"; it is lossless *for spaces and newlines*, and this is where the boundary is:

- **`'  indented'` loses one leading space.** That is `prepend_scheme=always` from step 1: a `▁` is added at
  the front, and the decoder strips one leading space to undo it — taking a real one with it. Set
  `prepend_scheme="never"` and this probe round-trips exactly. Measured both ways.
- **`'\ttab'` loses the tab entirely, in both schemes.** The token `'\t'` is present in the encoding —
  you can see it — and the Metaspace **decoder** drops it. `'x\ty'` decodes to `'xy'`.

On the whole corpus:

```text
ug.decode(ug.encode(text).ids) == text   ->   True
```

**Exact, on all 110,837 characters** — and now you know that is not the whole story. It is exact because
this corpus contains **zero tab characters** and does not begin with whitespace. Both losses above are
invisible to a corpus-level check.

That is Silent Failure #5 for the fifth time this week, and this time it caught *me*: the first draft of
this part claimed all these probes round-trip, on the strength of the corpus result. Measuring the probes
individually is what found the two that do not.

Compare part 1.4's WordPiece all the same: 1,646 newlines destroyed and 158 `#` characters mangled, on this
very corpus. Metaspace's losses need a tab or a leading space to appear; WordPiece's needed nothing.

### Step 3 — the three conventions, finally side by side

| | marker | in the vocabulary as | collides with real text? | whitespace round-trips? |
| --- | --- | --- | --- | --- |
| byte-level BPE (Day 13) | `Ġ` = U+0120 | `Ġplan` | **no** — U+0120 is unused in text | ✅ |
| WordPiece (part 1.2) | `##` on continuations | `plan`, `##s` | **yes** — measured, 158 `#` lost | ❌ |
| SentencePiece (here) | `▁` = U+2581 | `▁plan` | **no** — U+2581 is a drawing character | ✅ |

The pattern is now unmistakable. **Mark the space with a character text does not use, and you keep
losslessness. Mark the absence of a space with characters text does use, and you lose it.** Two independent
designs found the first answer; the one that took the second answer is the one that cannot round-trip.

### Step 4 — testing the slogan

If this really removed the pre-tokenizer, merges could cross former word boundaries and tokens spanning two
words would appear. Do they?

```python
vocab = [t for t, s in json.loads(ug.to_str())["model"]["vocab"]]
multiword = [t for t in vocab if t.count("▁") > 1]
print(f"{len(multiword)} of {len(vocab)} tokens span more than one word")
print(multiword[:10])
```

**Line by line:**

- `t.count("▁") > 1` finds tokens containing two or more space markers — necessarily spanning a word
  boundary, since each `▁` was a space.
- Counting rather than sampling, because the interesting answer is the proportion.

Measured:

```text
0 of 1000 tokens span more than one word
[]
```

**Zero.** Not a small number — none at all.

The reason is `split=True`, the third parameter from step 1. Metaspace still *cuts* at every `▁`, so a
candidate substring can never contain two of them, and the pool part
[2.1](../02-unigram/2.1-start-big-and-prune.md) enumerated never proposes one. "No pre-tokenizer" turns out
to be the wrong description of what this does.

The accurate description is: **it splits in the same places a whitespace pre-tokenizer would, and keeps
what it split on.** The chunking is unchanged from WordPiece; the whitespace survives as a character
attached to the following chunk. That is the entire difference, and it is smaller than the framing
"SentencePiece has no pre-tokenizer" suggests.

Set `split=False` and cross-word tokens become possible — along with a much larger candidate pool, since
substrings may then span any number of words. The default is a compromise, and knowing which half of it is
doing the work matters when you tune it.

---

## Shapes

| Name | Symbolic | Concrete | Meaning |
| --- | --- | --- | --- |
| input | `(n_chars,)` | `(20,)` | `The plan costs zero.` |
| after Metaspace | `(n_chars + 1,)` | `(21,)` | every space → `▁`, plus one prepended |
| chunks | `(n_chunks,)` | `(4,)` | split at `▁`, nothing discarded |
| `ids` | `(T,)` | `(4,)` | for this string |
| cross-word tokens in vocab | scalar | `0 / 1000` | `split=True` forbids them |

The `+1` in row two is `prepend_scheme=always`, and it is the single most consequential default in this
part — Day 14 part 3.3's bug was exactly this flag disagreeing between two machines.

---

## When it breaks

**`▁` is rare in text, not absent.** U+2581 is a box-drawing character used in terminal graphics, sparkline
charts and ASCII-art bar plots. A corpus of terminal output can contain it, and then it is
indistinguishable from a space marker — the same collision as `##`, just far less likely. The byte-level
`Ġ` approach is strictly safer here, because U+0120 arises from a byte mapping rather than being chosen
from real Unicode.

**`prepend_scheme` must match between training and serving.** It is Day 14 part 3.3's failure with a
different name. Flip it and `plan` tokenizes as a mid-sentence word or a string-initial one — different
ids, perfect round trips on both sides, no error. That day measured 4 of 4 probes disagreeing from exactly
this.

**Tabs are destroyed by the decoder.** Measured: `'x\ty'` encodes to `['▁', 'x', '\t', 'y']` — the tab
token is right there, visible in the output — and decodes to `'xy'`. Newlines survive; tabs do not. On this
corpus that is invisible because it contains **zero** tab characters; on a corpus of indented code it is
catastrophic and equally silent. Check it on your own text before trusting a corpus-level round trip.

**The decoder must use the same replacement.** `decoders.Metaspace()` reverses the substitution; omit it and
you get `▁` in user-visible output, which is Day 14 part 2.1's missing-decoder bug in this family's
clothing.

---

## In production

**This is why SentencePiece can claim to be language-agnostic.** Japanese, Chinese and Thai are written
without spaces, so a whitespace pre-tokenizer has nothing to split on and degrades to one chunk per
sentence. Metaspace makes no assumption that spaces exist — if there are none, there are no `▁` marks and
the model simply learns from the character stream. Day 14 part
[3.2](../../../day-014-tiktoken-and-the-pipeline/parts/03-the-remaining-gap/3.2-the-tax-a-vocabulary-charges-a-language.md)
measured Japanese still costing 3.65× on a modern vocabulary; the tax is real, and it is not made worse by
a pre-tokenizer that assumes English word shapes.

**"No pre-tokenizer" is not quite true and the difference matters at scale.** `split=True` still cuts at
`▁`, which bounds how far a merge can reach. Set `split=False` and the candidate pool from part
[2.1](../02-unigram/2.1-start-big-and-prune.md) grows enormously, because substrings may now span any
number of words. The default is a compromise, not an absence.

**The convention shows up in vocabulary files and is worth recognising on sight.** `▁the` means
SentencePiece or Metaspace; `Ġthe` means byte-level BPE; `##the` means WordPiece. Three markers, three
families, readable from one line of a vocabulary file — a genuinely useful thing to know when you inherit a
model with no documentation.

**Choose the marker before you train, because it cannot change afterwards.** The replacement character is
baked into every token string and therefore into every id. Day 14's file-is-the-contract argument applies
in full: it must travel with the vocabulary, and a serving stack that constructs `Metaspace()` in code
rather than loading it has reintroduced the mismatch.

## Check yourself

```python
import json
from pathlib import Path
from tokenizers import Tokenizer, models, pre_tokenizers, decoders, trainers

text = Path("docs/00_MASTER_PLAN.md").read_text(encoding="utf-8")
ug = Tokenizer(models.Unigram())
ug.pre_tokenizer = pre_tokenizers.Metaspace()
ug.decoder = decoders.Metaspace()
ug.train_from_iterator([text], trainers.UnigramTrainer(
    vocab_size=1000, show_progress=False, special_tokens=["<unk>"], unk_token="<unk>"))

# 1. the eval that can go red: spaces and newlines survive exactly
for s in ["The plan.", "a  b", "line1\nline2", "a\n\n\nb"]:
    assert ug.decode(ug.encode(s).ids) == s, \
        f"{s!r} -> {ug.decode(ug.encode(s).ids)!r} - metaspace should be lossless here"
print("4 space/newline probes round-trip exactly")

# 1b. and the two that do NOT - pin the boundary, not just the property
assert ug.decode(ug.encode("  indented").ids) == " indented", \
    "leading space survived - if prepend_scheme='never', this probe SHOULD round-trip"
assert ug.decode(ug.encode("x\ty").ids) == "xy", \
    "the tab survived - measured here, the Metaspace decoder drops it"
print("leading space and tab are lost - measured, not assumed")

# 2. and the whole corpus
assert ug.decode(ug.encode(text).ids) == text, "corpus round trip failed"
print(f"corpus: {len(text)} characters, exact round trip")

# 3. two spaces produce two markers - the count is preserved
toks = ug.encode("a  b").tokens
assert toks.count("▁") == 2, f"expected two bare markers, got {toks}"
print("'a  b' ->", toks)

# 4. how much did dropping the pre-tokenizer cost?
vocab = [t for t, s in json.loads(ug.to_str())["model"]["vocab"]]
multiword = [t for t in vocab if t.count("▁") > 1]
print(f"{len(multiword)}/{len(vocab)} tokens span more than one word")
assert multiword == [], \
    "a token spans two words - split=True should make that impossible"

# 5. the marker must not appear in the corpus, or it collides
assert "▁" not in text, \
    "your corpus contains U+2581 - it is indistinguishable from a space marker, exactly like ##"
print("U+2581 does not occur in the corpus, so the marker cannot be forged")
```

**Line by line:**

- Check 1 is the eval that can go red, and it is the *same probe list* part
  [1.2](../01-wordpiece/1.2-the-hash-hash-convention.md) used to assert WordPiece **fails**. Running
  identical probes across families, asserting failure in one and success in the other, is what turns two
  observations into a comparison.
- Check 3 counts bare `▁` tokens rather than checking the decode, because the decode already passed in
  check 1. This asserts the *mechanism* — two spaces became two markers — not just the outcome.
- Check 5 is the collision check, and it is the one to carry to any new corpus. It is exactly the assertion
  that would have failed for `##` on this markdown corpus, and running it is how you find out **before**
  training rather than after.
